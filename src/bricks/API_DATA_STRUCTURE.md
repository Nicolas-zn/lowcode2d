# Bricks 组件 API 数据结构文档

本文档说明各个 Brick 组件通过 API 接口获取数据时期望的数据格式。

## 通用说明

- 所有组件都支持配置 API 接口
- 当配置了 API 后，组件会优先使用 API 返回的数据，而不是默认 props
- API 自动每 30 秒刷新一次数据
- 如果 API 请求失败，组件会继续使用默认 props

---

## 1. TableBrick（表格组件）

### 数据结构

```json
{
  "columns": ["列名1", "列名2", "列名3"],
  "rows": [
    { "列名1": "值1", "列名2": "值2", "列名3": "值3" },
    { "列名1": "值4", "列名2": "值5", "列名3": "值6" }
  ]
}
```

### 字段说明

| 字段      | 类型          | 必填 | 说明                                           |
| --------- | ------------- | ---- | ---------------------------------------------- |
| `columns` | Array<string> | 否   | 表格列名数组，如果不提供会自动从第一行数据提取 |
| `rows`    | Array<Object> | 是   | 表格数据数组，每个对象代表一行数据             |

### 兼容格式

```json
// 格式 1: 标准格式
{
  "data": [
    { "姓名": "张三", "年龄": 28, "职位": "工程师" }
  ]
}

// 格式 2: 直接返回数组
[
  { "姓名": "张三", "年龄": 28, "职位": "工程师" },
  { "姓名": "李四", "年龄": 32, "职位": "产品经理" }
]
```

### 示例

```json
{
  "columns": ["姓名", "年龄", "职位", "部门"],
  "rows": [
    { "姓名": "张三", "年龄": 28, "职位": "工程师", "部门": "技术部" },
    { "姓名": "李四", "年龄": 32, "职位": "产品经理", "部门": "产品部" },
    { "姓名": "王五", "年龄": 25, "职位": "设计师", "部门": "设计部" }
  ]
}
```

## 2. EChartBrick（柱状图组件）

### 数据结构

```json
{
  "xAxis": ["类目1", "类目2", "类目3"],
  "series": [
    {
      "name": "系列名称",
      "data": [100, 200, 150],
      "color": "#667eea"
    }
  ]
}
```

### 字段说明

| 字段             | 类型          | 必填 | 说明                 |
| ---------------- | ------------- | ---- | -------------------- |
| `xAxis`          | Array<string> | 是   | X 轴类目数据         |
| `series`         | Array<Object> | 是   | 系列数据数组         |
| `series[].name`  | string        | 是   | 系列名称             |
| `series[].data`  | Array<number> | 是   | 系列数据值           |
| `series[].color` | string        | 否   | 系列颜色（十六进制） |

### 兼容格式

```json
// 包装在 data 字段中
{
  "data": {
    "xAxis": ["周一", "周二", "周三"],
    "series": [...]
  }
}
```

### 示例

```json
{
  "xAxis": ["周一", "周二", "周三", "周四", "周五"],
  "series": [
    {
      "name": "销售额",
      "data": [120, 200, 150, 80, 70],
      "color": "#667eea"
    },
    {
      "name": "利润",
      "data": [30, 50, 40, 20, 15],
      "color": "#764ba2"
    }
  ]
}
```

## API 配置说明

### 配置界面

在画布编辑模式下，点击组件工具栏中的"接口配置"按钮，配置以下信息：

- **请求地址**：API 基础地址，默认：`http://localhost:3001`
- **请求后缀**：具体接口路径，例如：`/api/users`
- **请求方法**：GET、POST、PUT、DELETE、PATCH
- **Token**：身份验证令牌，默认已填充

### 完整请求 URL

系统会自动拼接：`请求地址` + `请求后缀`

例如：

- 请求地址：`http://localhost:3001`
- 请求后缀：`/api/sales/data`
- 完整 URL：`http://localhost:3001api/sales/data`

### 请求头

所有请求都会自动添加以下请求头：

```
Content-Type: application/json
Authorization: Bearer {token}
```

## 最佳实践

### 1. 统一数据格式

建议后端 API 统一返回格式：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    // 具体组件需要的数据
  }
}
```

组件会自动提取 `data` 字段中的数据。

### 2. 错误处理

当 API 请求失败时，组件会：

1. 在控制台输出错误信息
2. 继续使用默认 props 显示数据
3. 不会中断页面渲染

### 3. 数据刷新

- 组件会在首次加载和配置变更时请求 API
- 之后每 30 秒自动刷新一次数据
- 适合实时数据监控场景

### 4. 性能优化

- 使用相同 API 的组件可以考虑在后端合并数据
- 避免配置过于频繁的刷新间隔
- 大数据量时建议后端分页返回

## 常见问题

### Q1: API 返回的数据格式不匹配怎么办？

A: 有以下解决方案：

1. 后端调整 API 返回格式
2. 使用中间层转换数据格式
3. 联系开发团队定制组件

### Q2: 如何调试 API 数据？

A: 打开浏览器控制台（F12），查看：

- Network 标签：查看 API 请求和响应
- Console 标签：查看错误信息

### Q3: 能否使用 POST 请求？

A: 可以，在接口配置中选择 POST 方法。但目前不支持自定义请求体（body）。

### Q4: Token 如何获取？

A: 请联系后端开发人员获取有效的 API Token。
